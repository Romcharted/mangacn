# AGENTS.md — working on mangacn

mangacn is a shadcn/ui registry served straight from this GitHub repository. It **dresses** shadcn
components in a manga style; it never rewrites them. Read this file before changing anything.

## Ground rules

- Everything in the repo is in English: code, names, docs, showcase copy, registry descriptions.
- Registry items are 100 % frontend: props in, callbacks out. No backend, database, account, analytics or
  paid service. (The showcase alone may load cookieless Umami statistics when it is configured.)
- Nothing copied: no character, logo, title, page or brand colour from an existing work or platform.
  Demo art comes from "Mapless", the showcase's own invented series (Suzu, Kuro, the Eraser): five
  AI-generated images and crops of them, in `site/public/art/` with their `CREDITS.md`, built by
  `scripts/art-images.py` (WebP, several widths, never toned again). Say they are AI-generated wherever they are
  credited (README, `CREDITS.md`, the site footer). No other demo drawings: no shapes, silhouettes, figures made
  of circles or abstract covers standing in for art; UI icons are not art. Registry items ship no image:
  components and blocks take picture URLs as props, and the site passes the Mapless files. A freely licensed
  picture may be added only with its source, author and license in that `CREDITS.md`; never a work whose author
  refuses AI derivations.
- Each item has its own file, `registry/items/<name>.json`, the source of truth for that item.
  `registry/index.json` lists them (`include`) and `npm run sync` assembles `registry.json`, from which
  `llms.txt`, the README list and `r/*.json` are generated. Never edit `registry.json` by hand.

## Layout

```
registry/items/<name>.json    # one item per file (description, docs, meta.tagline/usage/props, files)
registry/index.json           # registry name, homepage and the ordered `include` list of item files
registry.json                 # generated by `npm run sync`: never edit
registry/manga/base/          # mangacn.css -> synced into registry/items/base.json (tokens, utilities, grammar)
registry/manga/lib/           # gestures.tsx: the JavaScript half of the grammar (impact, focus flash)
registry/manga/ui/            # restyled shadcn components (thin wrappers)
registry/manga/signature/     # manga components (SpeechBubble, Screentone, ...)
registry/manga/webtoon/       # webtoon components (drawn in ink)
registry/manga/blocks/        # full interfaces (registry:block), one folder each
site/                         # one-page showcase (Vite + React 19 + Tailwind v4), gallery + detail by #hash
site/src/demos/<item>.tsx     # optional Preview, States (frozen tiles) and Thumb (gallery card) exports
site/src/pages/               # example manga pages (JSX and PageData) and the page format doc
site/src/studio/              # the page studio (#studio): edits PageData, exports JSX, JSON and PNG
scripts/                      # sync-base, assemble-registry, llms.txt + README list, check-items, screenshots
```

## Adding a restyled shadcn component

1. Install the stock component in the showcase: `npx shadcn@latest add <name>` (lands in `site/src/components/ui`).
2. Write `registry/manga/ui/<name>.tsx`: import from `@/components/ui/<name>`, add classes and `data-*`
   attributes, re-export the same API. Do not use props that only exist in Radix or only in Base UI.
3. Write the item file `registry/items/<name>.json` (`title`, `description` for AIs, `meta.tagline` for humans: one short
   sentence, `categories`, `registryDependencies: ["<name>", "Romcharted/mangacn/base"]`, `dependencies: ["cn"]`,
   `files` with `target: "@ui/manga/<name>.tsx"`, `docs`, `meta.usage`, `meta.props`).
   A bare name (`button`) is the official shadcn item. An item from this repo is always `Romcharted/mangacn/<item>`.
   Then list the file in `registry/index.json` → `include` (in a wave, the orchestrator does this step).
   Manga pieces: `registry/manga/signature/<name>.tsx`, type `registry:component`, target
   `@components/manga/<name>.tsx`, `registryDependencies: ["Romcharted/mangacn/base"]` (+ gestures or ui items used).
4. Add `site/src/demos/<name>.tsx` exporting `Preview` (live), `States` (labelled tiles, every variant × state,
   frozen) and `Thumb` (small, non-interactive gallery preview).
5. `npm run build && npm run shots -- --only <view>`, look at the screenshots in light and dark, then commit
   (one commit per component).

Categories (first one decides the showcase section): `foundations`, `actions`, `feedback`, `overlays`,
`navigation`, `display`, `manga`, `webtoon`, `blocks`.

### Wrapper pitfalls (learned the hard way)

- **Write every class literally.** Tailwind scans source text: `${prefix}:rounded-none` is never generated.
- **Cover both libraries' state hooks.** Prefer ARIA (`aria-checked`, `aria-selected`, `aria-invalid`,
  `aria-disabled`), which Radix and Base UI both set. Base UI marks disabled tabs with `aria-disabled`, and
  stock shadcn fades it with `aria-disabled:opacity-50`: always add `aria-disabled:opacity-100`.
- **Stock classes keep their opacity, blur and sizes.** Override every `/50`, `opacity-50`, `ring-*/50`,
  `backdrop-blur`, `animate-in fade-*`, and stock size classes (use `!` when they are more specific).
- **Corners follow `--radius`** (`rounded-(--radius)`), never `rounded-none`.
- **Shapes that clip** (`shape-burst`, `edge-jagged`) go on a `::before` fill, so the focus ring is not clipped.
  A burst's focus ring is a larger burst with a paper gap.
- **`tone-shadow` uses `::after`.** Do not use it where the library owns the pseudo-elements (Sonner toasts
  use an offset second frame instead).
- **Overlays** (dialog, sheet, drawer) get their light screentone veil from base; never style them per component.
- **Static twins for overlays**: export a static look-alike (`ToastCard`, `TooltipBubble`) sharing the same
  classes, so state grids can show frozen overlays.
- **shadcn's own data-* variants:** `data-selected:`, `data-open:` and friends are redefined by
  `shadcn/tailwind.css` (e.g. `data-selected` = `[data-selected="true"]`). Base UI sets empty attributes
  (`data-selected=""`), so use the arbitrary form `data-[selected]:`.
- **`!important` beats animations.** A colour set with `bg-x!` cannot be animated; `fill-in` paints with
  background layers and `-webkit-text-fill-color` so it still works over important colours.
- **Next.js:** files with hooks or event handlers start with `"use client"`. Next templates set
  `--font-sans` (Geist) on `<html>`, so base sets the body font from `--font-manga-body` directly.
- **Never `in-*` for a state.** `in-active:`, `in-data-[x]:` and friends match *any* ancestor: `:active` is true
  for every ancestor of the pressed element up to `<html>`, so a click anywhere lit every button's impact lines.
  Use the direct parent (`[:active>&]:`, `[[data-side=top]>&]:`) or a named group on the owner (`group/x`,
  `group-data-[x]/x:`).
- **Segments of a group keep their focus inside** (tabs, toggle groups, button groups, pagination cells):
  `focus-visible:outline-2! focus-visible:outline-offset-[-Npx]! focus-visible:shadow-none!`, so the ring never
  overlaps a neighbour or the panel.
- **Names that ad blockers stop:** no file or item called hit-counter, counter, analytics, tracking, ads or
  advert. A blocked module leaves the whole showcase blank in development, and a blocked `r/<name>.json`
  cannot be installed. (HitCounter became ImpactCounter for this reason.)
- **Restate the outline style when you move a focus ring.** Stock classes can set `outline-style: none`;
  overriding only the width and offset leaves no ring at all. Write `focus-visible:outline-solid!` (and the
  colour) with the offset, then check the focus tile.
- **`cn` here does not merge classes.** A colour or border passed through `className` does not reliably
  replace the component's own: give the component a prop (Stamp `tone`) instead of overriding from outside.
- **Library-specific props stay out of registry files and blocks:** no `render`, no `asChild`, no Toggle
  Group `type` / array values. Style a trigger with a class helper (`buttonClassName()`) or use plain pressed
  buttons.
- **Bars sit on their line, in whole pixels.** An underline bar shares the outer edge of its 2px baseline and
  grows inward (hover 4px, selected 6px). Never `calc(… + 1.5px)`.
- **shadcn's Tabs drops `orientation`** before the primitive (both versions): the wrapper adds
  `aria-orientation` and the up/down arrows itself. Check every `orientation` prop the same way.
- **Showcase only:** `data-force="hover|focus|active"` freezes a state in the tiles (see `vite.config.ts`).
- **Demos never navigate.** Links in a demo use `href="#"` (the router ignores a click on it) and keep their own
  state: clicking page 3 makes page 3 current. Links home are `#/`.
- **`bg-muted` is a light tone in base.** A stock part that uses `bg-muted` behind text (code lines, attachment
  media) breaks Rule A: add `bg-none!` next to `bg-transparent!`.
- **Dress, never rewrite.** Even when many stock classes need overriding, wrap the stock part and beat its classes
  with `!` (Code Block came back once for redrawing every part).
- **Hidden helpers need a positioned owner.** An `sr-only` caption or live region escapes a scroll frame unless an
  ancestor inside the component is `relative` (ReaderStrip).
- **Invisible impact lines still take room.** A chip or button at the end edge of a wrapping row pushes its
  `ImpactLines` past the container: leave `pe-4` on the row (ReactionPicker).
- **MessageScroller items use `content-visibility: auto`:** full-page captures and "scroll to end" can show blank
  areas; demos and blocks that must render everything set `[content-visibility:visible]!` on the items.
- **A new block folder** may not be picked up by the dev server's glob until `site/src/interfaces.tsx` is touched.

## Grammar — eight gestures

A component never draws its own hover, selection or entrance: it applies a gesture. Each gesture is a
utility in `base` or a small primitive in `gestures`. Cadence: 12 frames per second (83 ms a frame); a
gesture lasts 2 to 4 frames (166–333 ms), always in `steps()`. With `prefers-reduced-motion` nothing
moves and every state stays distinct (hidden effects such as lines start `invisible`).
**Exception — what a finger drags follows the finger, without steps.** While a drawer, a resizable handle, a
slider thumb or a carousel strip is being dragged, it moves with the pointer, continuously and with no delay;
the steps come back only for what the component does on its own (opening, closing, snapping).
The showcase has a Grammar page (`#grammar`) that replays each one.

| # | Gesture | When | How |
| --- | --- | --- | --- |
| G1 | Case | Every container: card, panel, window, list, field | `ink-case` (paper, 3px ink line, tone shadow; needs a positioned element). Inside a case: `ink-case-inner` (2px, no shadow) |
| G2 | Flat | Selected, checked, active, current | `ink-fill` + `fill-in` (sweeps in over three frames in the reading direction). Bars: `animate-bar-in` |
| G3 | Hover | Every interactive element | Framed: `hover-lift` (tone shadow appears at 2px, moves to 4px). Frameless: `hover-invert` or `hover-underline`. Elements of 24px or less, fields and cells of a group: `hover-thicken` (the line thickens by 1px, inside). Never a tone behind text |
| G4 | Impact | Every click or validation | `data-[impact]:animate-hit` + `<ImpactLines />` + `withImpact(onClick)` / `punch(el)`. Without JavaScript the press still hits: explicit pressed negative, `press` (2px offset) and the lines while `:active` |
| G5 | Pop | Whatever appears | `animate-pop` (0.9 → 1.05 → 1). Optional halo around a window: `<FocusFlash />` (Dialog `flash`, off by default, never full screen). Panels that slide: `animate-slide-in`; content that unfolds: `animate-drop-in` |
| G6 | Bubble | Whatever floats and points | Tooltip / popover / hover card: a bubble with a tail (`<BubbleTail />`). Lists and menus: `ink-case case-notch` (notch toward the trigger, from `data-side`) |
| G7 | Running line | Progress, waiting, value | `fill-lines`; waiting: `Spinner` (`animate-spin-steps`) |
| G8 | Mark | Status and emotion | Error: `mark-error`, `edge-jagged` (32px+), `animate-shake`. New: `shape-burst`. Done: `mark-check`. Brush shapes: `mark-chevron`, `mark-arrow`. Manpu marks |

Disabled is not a gesture and does not change: dashed line, tone frame, label on paper, not-allowed cursor.

**Control rule:** if a component needs something the grammar does not cover, do not invent it silently:
write it in "Special cases" below and flag it.

### Kit rules (decided cases)

These started as special cases and are now rules of the kit. New ones go through the control rule above.

- **Hover:** tabs `index` thicken their top line (no tone shadow per tab); elements of 24px or less, fields
  and the cells of a group use `hover-thicken` (G3, third case).
- **Motion variants of G5:** content that slides (`animate-slide-in`, `animate-sheet-in`) or unfolds
  (`animate-drop-in`) where a scale would look wrong.
- **G4 needs JavaScript** for the full three frames (the `gestures` item); without it the press still shows
  the negative, the 2px offset and the lines.
- **Round shapes:** only speech bubbles are round. Radio Group items are diamonds; Avatars are squares.
- **Spinner** draws its own concentration lines instead of wrapping the stock icon; same props.
- **Choice cards** (Field): checked is a 6px ink bar at the start, like a selected table row, not a full ink
  flat (the card holds a control and text that would all have to invert).
- **Dashes mean "disabled", and only that:** Empty uses a solid line, the Stepper rail ahead of the current
  step is a fine solid line.
- **Sheet:** its shadow is an offset second frame on the open side, not a tone block.
- **Alert Dialog:** Action and Cancel are the stock elements drawn with `buttonClassName()`; they hit on click
  but have no burst focus.
- **Bubble (chat):** `default` is an ink bubble (your own messages); the other variants are paper bubbles.
- **Overlay veils** (dialog, alert dialog, sheet, drawer): a paper wash under wide dots, from base, so the page
  behind goes quiet.
- **Library-specific parts are not wrapped:** if one version of shadcn (Radix or Base UI) lacks a part, the
  wrapper leaves it out (Progress only wraps `Progress`).
- **Drop zones** (Attachment `idle`): a solid 2px line and a "+" mark, never the stock dashes (dashes mean disabled).
- **Code is monochrome** (Code Block): highlighter tokens are drawn in ink; marked lines carry the 6px bar.
- **Trace status mark** (optional): an empty `TraceIcon` draws the line's status mark; your own icon replaces it.
- **Choice bars grow** (Field, Questionnaire): the 6px bar of a checked choice grows down with `animate-bar-in` (G2).
- **Thin running bars** (ReadingProgress): at 4px the bar is solid ink; its paper speed line shows only at 6px.
- **Failed pages** (ReaderStrip): a jagged panel filled with the accent, paper text on it, like a destructive button.
- **Shouted errors** (AI chat): a shout bubble's outline takes the accent (`--bubble-stroke: var(--destructive)`).
- **Small buttons that invert on hover** (Input Group button, Combobox trigger and clear): pressed is an ink
  flat with a 2px paper line inside and the 2px offset, so it never looks like hover. A chip's remove cell:
  pressed is paper with an ink x (the negative of hover); its focus stays inside the chip.
- **Day cells** (Calendar) draw their hover line with a shared inset shadow, so it combines with the today
  frame and the range band; it looks the same as `hover-thicken`.
- **Dots of a group** (Carousel dots): focus is a 2px line inside the hit area, not the full double ring.
- **Draggable lines** (Resizable handle): hover thickens the 2px line to 4px, 1px on each side.
- **Radix-required props in blocks:** when Radix needs a prop Base UI ignores (Accordion `type`), pass it
  through a loosely typed spread (`const MODE = { type: "multiple" } as unknown as ComponentProps<…>`).
- **Waiting caret and date mark:** `animate-blink` (two hard steps) and `mark-calendar` come from base.
- **Showcase helper `ForceInside`** (`site/src/force-inside.tsx`): freezes a state on a part a component draws
  inside itself (a spine, a thumbnail, a page edge) by setting `data-force` there, without widening the
  component's API. It is the standard way to show internal states in the tiles.

### Pages, narration and reading (decided cases)

- **Page pieces are direct children:** `Tier`, `Column` and `Panel` are direct children of `Page` / `Tier` / `Column`
  (or in a fragment), never wrapped in a component of your own: the page reads them to lay itself out.
- **Inside a page, sizes are page units:** a page is 100 units wide; `--pu` (registered in base) is one unit, and
  the page sets `--bubble-size`, `--caption-size`, `--sfx-sm…xl` and `--page-fine` from it. A piece that may sit on
  a page switches to them with `[[data-manga=page]_&]:` (an ancestor selector, more specific than a class, unlike
  `in-*`). Any drawn piece that must keep its proportions from thumbnail to full screen sizes its lettering in
  container units (`cqi`).
- **A page in a small space sets `line` and `lettering`** from its measured width (a strip panel is a small page).
- **A bubble on a page is a superellipse** (exponent 3): a pure oval does not hold a block of several lines.
- **Tails aim:** a bubble placed on a page aims its tail with `pointAt` (percent of the panel) rather than a side.
- **Scene change (SceneTransition), accepted exception to the 2–4 frames rule:** cover in 4 frames, hold 2, uncover in 4 (10 frames, 833ms). Longer than a
  gesture because it changes the scene, not an element; `animate-wipe` / `animate-wipe-out` in base do one half
  without JavaScript.
- **Hidden reading (Ruby `reveal="hover"`):** the text stays in place, transparent (read aloud); hover is a dotted
  underline that thickens.
- **Name plates and labels** (DialogueBox name, VolumeCard volume): an ink flat used as a label, not a selected state.
- **"Continue" arrow** of a reader or dialogue: `animate-blink`, like the waiting caret (G7).
- **Two languages in one place** (BilingualBubble): both in the same grid cell, the hidden one `invisible` and
  `aria-hidden`, so switching never reflows.
- **Edge band beside vertical text** (ChapterTitle): `tone-lines` in a narrow band next to the text column (Rule A).
- **Page edges of a reader** (PageReader): an invisible full-height hit zone; on hover only, a paper plate with a
  brush arrow and the tone shadow; pressed, the plate turns to an ink flat. Never on touch screens.
- **A page turn is G5 sliding:** the page comes from the side it was turned from (`animate-slide-in`, reversed in
  manga order); the loaded image does not also pop.
- **A pulled spine** (Shelf): selected is the ink flat plus a 16px rise in two steps (the book leaves the row).
- **Inline spoiler under 24px:** no tone (Rule C), the hidden text is an ink flat; hover is a paper line inside.
- **Guided reading** (GuidedView): around the panel being read, an opaque paper veil of wide dots that clears while
  the camera moves; the camera goes from panel to panel in four steps (333ms, G5); in the whole-page view the
  current panel has a 6px inner double line, paper then ink (no flat on art); hover thickens it.

### Recipes that shadcn documents but does not ship

Data Table, Date Picker and Typography are documentation recipes, not registry items. mangacn ships them as
items of its own (`data-table` on `@tanstack/react-table` + Table, `date-picker` on Popover + Calendar,
`typography` as plain styled elements). Form and Toast are official items: Toast is superseded by Sonner.

## Working in waves (orchestrator and subagents)

Large batches are built by subagents, 4 or 5 at a time, each with 3 to 5 components of one family.

- **Frozen during a wave:** `registry/manga/base/`, `registry/manga/lib/`, this file, `registry/index.json`,
  `registry.json`, `site/src/app.tsx`, the scripts, `package.json`, `site/src/components/ui/`.
  If something is missing from the base, a subagent asks for it instead of adding it.
- **Model component per family** (read it before writing): lists and menus → `select.tsx`; navigation →
  `tabs.tsx`; windows and floating panels → `dialog.tsx`; drawn pieces → `signature/speech-bubble.tsx`.
- **A subagent touches only its own files:** `registry/manga/ui/<name>.tsx` or `registry/manga/signature/<name>.tsx`,
  `site/src/demos/<name>.tsx`, `registry/items/<name>.json`. Nothing else.
- **It delivers, per component:** the component file, its demo (`Preview` live, `States` with every variant ×
  state as frozen labelled tiles, `Thumb`), the tagline (one short sentence), the props, the item file.
- **It checks** with `npx tsc -p tsconfig.json --noEmit` and the screenshot helper, then reports: files written,
  what it could not do, and every special rule it needed (never invented silently).
- **After the wave** the orchestrator includes the items, builds, takes screenshots, compares each component with
  the grammar and its model, sends back what strays, installs the batch in four fresh projects, then builds the
  interfaces that combine several components.

## Style rules

- **Two values plus one accent**: ink (near black) and paper (warm white); dark mode is the negative.
  One accent, `--mg-accent` (stamp red by default; presets `data-accent="indigo|pine|ochre"`), used for
  destructive actions, errors and rare highlights. It also drives `--destructive`.
- **Variables**: `--background` paper, `--foreground` ink, `--primary` ink, `--primary-foreground` paper,
  `--border` ink, `--ring` ink, `--destructive` accent, `--radius: 0`. `--muted` / `--secondary` are paper.
- **Line**: 2 px by default (`border-ink`), 3 px for panels and windows (`border-ink-panel`), 1 px for details
  (`border-ink-fine`). Sharp corners. Only speech bubbles are round.
- **Tones replace grey**: `tone-10/20/35/50` (dots at 45°), `tone-lines`, `tone-cross`, `tone-fade-*`,
  `tone-frame`. Never opacity, never a smooth gradient to shade.
- **Shadows**: no blur, ever. A shadow is an offset block of tone (`tone-shadow`). No solid black offset
  shadow with bright colours: that is neo-brutalism, not this kit.
- **Selected / active / checked**: a flat of ink with paper text (`ink-fill`).
- **Touch targets**: designed at 375 px first. On touch screens (`pointer: coarse`) every small control
  (Checkbox, Radio, Switch, Toggle, Button of any size) carries `touch-hit`: an invisible `::after` grows the hit
  area to at least 44 × 44 px around its centre, without changing the drawing. The element must be `relative`.
  A component that draws with `::after` only while pressed or during an effect (`:active`, `data-fx`) keeps it:
  `touch-hit` steps aside then. A new small control gets `touch-hit` too; the showcase's own controls are 44 px
  tall under 640 px.
- **Energy**: `speed-lines`, `focus-lines`, `shape-burst` — around content, never under a label.
- **Type**: reading face for body and fields (`font-sans`), lettering face for titles, buttons, badges
  (`font-letter`), SFX face that covers katakana (`font-sfx`). Google Fonts, OFL only.
- **Motion**: stepped, ~12 fps, 80–240 ms. Pressed controls show an explicit negative (not a filter).
  Shake on error. With `prefers-reduced-motion` no animation, but every state stays distinct.

### Rule A — a label never sits on a tone or under lines

Reading text rests on a flat (paper or ink). Tones and lines live around it: in the shadow, as an inner
frame (`tone-frame`), as a band on an edge, or behind a plate (`on-tone`: paper, 2 px / 6 px). The
`knockout` text outline is only for very heavy SFX lettering.

### Rule B — hover and disabled never look alike

Light tone + dashed border = disabled, and nothing else. Hover = inversion, a flat, a thicker line or a
tone shadow that appears/shifts — never a background tone. Disabled keeps the label on paper, AA contrast,
`cursor: not-allowed`.

### Rule C — no screentone inside an element smaller than 24 px

Under 24 px a tone is noise. Use line weight, dashes and flats (checkbox, switch, small badges). Serrated
edges (`edge-jagged`) only on elements 32 px tall and up.

### States every interactive component must show

| State | Look |
| --- | --- |
| hover | tone shadow appears or shifts, inversion, or a thicker line |
| pressed | 2 px offset + negative (visible on paper and on ink) |
| focus-visible | double line ink / paper / ink (`focus-ink`), following the shape |
| disabled | dashed border + tone frame, label on paper, not-allowed cursor |
| selected / checked | ink flat (`ink-fill`) |
| error | accent colour, serrated edge (32 px+), a "!" mark |
| loading | concentration lines turning in steps (`Spinner`) |

### Reading order and writing direction

- **Manga reading order** (`data-reading="rtl"`, `reading-rtl:` variant): panels, bubbles, carousels and
  pagination flow right to left; English text stays left to right. The showcase toggle drives this.
- **Writing direction** (`dir="rtl"`, Arabic or Hebrew): supported with logical properties
  (`ms-`, `pe-`, `start-`), tested separately (`?dir=rtl`).

### Accessibility

AA contrast everywhere. A tone never carries information alone. Keyboard and ARIA behaviour come from
shadcn: do not override them. Decorative onomatopoeia are `aria-hidden`.
